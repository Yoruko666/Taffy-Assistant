## 一、测试计划

### 1.1 测试目标

1. 验证系统**功能正确性**：13 个用例（UC-01 ~ UC-13）中至少 5 个可演示用例 100% 通过；
2. 验证系统**接口稳定性**：REST + WebSocket + LLM Tool Call 全链路无阻塞型缺陷；
3. 验证系统**非功能指标**：端到端语音回复 < 3s（首字 < 1.5s）、TTS 合成 < 2s；
4. 形成**可复用的测试资产**：用例库 ≥ 40 条，缺陷登记表完整，作为后续维护回归基线。

### 1.2 测试范围

#### 1.2.1 包含（In-Scope）

| 测试类型 | 覆盖对象 |
|---|---|
| 功能测试 | UC-01/02/04/05/06/07/10 主流程 + 边界条件 |
| 接口测试 | `/api/v1/auth/*`、`/api/v1/devices/*`、`/v1/voice` WS、`/v1/orchestrate` WS |
| LLM Tool Call 测试 | `control_device` 各 action 分支、设备上下文注入、二轮回复 |
| 鉴权测试 | JWT 中间件、`/v1/voice` 的 device_id/token 校验、401/403/404 错误码 |
| 异常测试 | 网络断连、LLM 超时、ASR 静音、设备离线、参数缺失/越界 |
| 性能测试 | 首字延迟、Tool Call 往返、TTS 合成时长、并发会话数 |
| 兼容性测试 | Android 模拟器（API 33）+ 真机（任选）；Windows / Linux 服务端 |
| 安装与部署 | 一键启动脚本 `scripts/start-all.ps1` / 手动分步 |

#### 1.2.2 不包含（Out-of-Scope）

- iOS 客户端（不在交付物内）
- 高并发压测（≥ 100 同时在线，超出"演示项目"定位）
- 真实硬件设备（ESP32/树莓派）的电气测试
- 安全渗透测试（仅做基础鉴权与越权检查）
- LLM 内容安全 / 多轮记忆等智能性评测（仅做"是否调用 tool 正确"的功能性测试）

### 1.3 测试策略

| 维度 | 策略 |
|---|---|
| **测试分层** | 单元测试（各模块组员自测） → 集成测试（W7 联调） → 系统测试（端到端用例） → 验收测试（演示日） |
| **测试方法** | 黑盒为主（对接口/UI），灰盒辅助（看日志辅助定位） |
| **执行节奏** | 编码阶段穿插冒烟测试 → W7 集中执行系统测试 → W8 演示前回归 |
| **缺陷管理** | GitHub Issues 登记，标签 `bug:p0/p1/p2`；每条缺陷必须有"复现步骤 + 期望/实际 + 修复 commit" |
| **回归策略** | 每次合 PR 必须重跑相关链路冒烟用例（5 条以内）；演示前一日跑全量 |

| 风险 | 影响 | 应对 |
|---|---|---|

| ASR 识别错（"开"听成"看"） | UC-06 失败 | 演示用固定句式 + 多轮重试；记录识别准确率 |
| 麦克风环境噪声 | VAD 提前/延迟断句 | 演示前现场试录；调整 `aggressiveness=2` 与 `silence_ms=800` |
| 数据库未初始化 | 全部用例 fail | 自动化检查脚本（health 接口）作为前置门禁 |
| 演示设备网络故障 | 现场翻车 | 提前一天彩排；移动热点；离线视频 |
